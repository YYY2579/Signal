# 配置指南

本文提供完成具体配置任务的操作步骤。完整默认值和来源限制见[能力参考](reference.md)，数据如何保存和发送见[隐私与本地数据](privacy.md)。

## 管理数据源

1. 打开右上角“设置”，选择“数据源”。
2. 使用“同步”开关决定是否启动该来源的定时抓取。
3. 使用“订阅”开关决定该来源是否出现在“我的订阅”工作区。订阅不会自动启用同步，启用同步也不会自动改变订阅状态。
4. 在“间隔”输入框中填写分钟数。支持 `1` 到 `1440` 分钟，失去焦点后保存并热重启该来源的调度任务。
5. 需要立即更新时，使用顶部刷新按钮。刷新全部来源时只请求当前已启用的数据源。

应用启动后，每个已启用来源会立即执行一次同步，之后按各自间隔运行。上游限流、登录墙、接口变更或网络错误可能导致单次同步失败；这不会把占位文章写入数据库。

Reddit 默认关闭。在当前匿名访问环境中，上游可能返回 HTTP 403；只有确认所在网络可以匿名访问该接口后再启用。Product Hunt 当前没有注册为数据源，不能仅通过设置打开。

## 配置掘金或知乎 Cookie

掘金和知乎的公开列表无需登录即可尝试同步。Signal 也允许把可选 Cookie 附加到这两个来源的请求：

1. 在已登录的浏览器会话中取得对应站点的 Cookie 请求头值。
2. 打开“设置 > 来源登录”。
3. 在对应来源中填入 `name=value; another=value` 形式的值，不要包含 `Cookie:` 前缀。
4. 点击“保存登录态”，再手动刷新该来源。

Cookie 会保存在应用的本地设置文件中，而不是系统凭据存储。它具有账号访问风险，不应粘贴到 issue、日志或聊天中；共享设备上应谨慎使用并及时清除。

当前限制：知乎阅读区只缓存热榜条目的摘要，不会因为配置 Cookie 就抓取完整回答；Cookie 只影响对应请求是否携带登录态。上游随时可能更改接口或拒绝自动请求。

## 配置关键词过滤

1. 打开“设置 > 关键词过滤”。
2. 选择“黑名单”以隐藏包含任一关键词的条目，或选择“白名单”以只保留至少包含一个关键词的条目。
3. 输入关键词并按 Enter 或点击“添加”。
4. 点击已有关键词旁的删除按钮即可移除。

匹配不区分大小写，作用于文章标题和摘要。本地全文搜索和各工作区读取都会使用当前过滤配置；白名单为空时不限制结果。

## 配置 AI Provider

打开“设置 > AI”，按所用协议填写以下内容：

| 协议 | 默认 API 地址 | 请求接口 | API Key |
|---|---|---|---|
| OpenAI Compatible | `https://api.openai.com/v1` | Chat Completions | 必需 |
| Anthropic Messages | `https://api.anthropic.com` | `/v1/messages` | 必需 |
| Google Gemini | `https://generativelanguage.googleapis.com` | `generateContent` | 必需 |
| Ollama | `http://localhost:11434` | `/api/chat` | 不需要 |

配置步骤：

1. 选择 Provider。切换 Provider 时，如果仍在使用上一协议的默认地址，界面会自动换成新协议的默认地址。
2. 填写服务端实际存在的模型名称。Signal 不自动下载模型，也不猜测账号可用模型。
3. 确认 API 地址。远程地址必须使用 HTTPS；HTTP 只允许 `localhost`、`127.0.0.1` 或 IPv6 回环地址。地址不能包含用户名、密码、查询参数或片段。
4. 云协议输入 API Key 并点击“保存”。凭据按协议分别写入操作系统凭据存储，不进入 SQLite 或 `settings.json`。Ollama 不读取云协议凭据。
5. 选择是否启用“生成后人工审核”。默认开启，结果先保存为可编辑草稿；关闭后生成结果直接标记为已接受，但不会自动创建知识库笔记。
6. 点击“测试连接”。测试会检查服务地址、凭据和所填模型是否可访问，不会评价模型能否稳定遵循 Signal 所需的结构化 JSON 输出。
7. 打开一篇有摘要或缓存正文的文章，确认发送内容后生成一次洞察，完成端到端验证。

OpenAI Compatible 表示服务需要兼容当前使用的 Chat Completions 请求和响应格式。DeepSeek、通义千问、Moonshot、GLM、硅基流动、vLLM、LM Studio 等服务可按兼容端点配置，但具体模型、路径、鉴权和 `response_format` 支持仍由服务提供方决定。

## 使用 Ollama

1. 安装并启动 Ollama。
2. 在终端准备模型，例如 `ollama pull qwen3:8b`。
3. 在 Signal 中选择“Ollama”，保持默认地址或填写实际本机地址。
4. 模型名称必须与 `ollama list` 中显示的名称一致。
5. 点击“测试连接”，再对一篇文章执行生成。

Signal 不负责启动 Ollama。若服务未监听、模型未下载或模型不支持稳定 JSON 输出，连接或生成会失败。

## 更换或删除 API Key

每个云协议使用独立凭据。切换 Provider 不会把一个协议的 Key 复制给另一个协议。

- 在 API 凭据输入框填写新值并点击“替换”，即可覆盖当前协议的 Key。
- 点击“移除”，再点击一次“确认”，即可删除当前协议的 Key。
- 删除 Key 不会删除本地文章、AI 历史结果或模型地址设置。
