# 配置指南

本文提供完成具体配置任务的操作步骤。完整默认值和来源限制见[能力参考](reference.md)，数据如何保存和发送见[隐私与本地数据](privacy.md)。

## 管理数据源

1. 打开右上角“设置”，选择“数据源”。
2. 使用“同步”开关决定是否启动该来源的定时抓取。
3. 使用“订阅”开关决定该来源是否出现在“我的订阅”工作区。订阅不会自动启用同步，启用同步也不会自动改变订阅状态。
4. 在“间隔”输入框中填写分钟数。支持 `1` 到 `1440` 分钟，失去焦点后保存并热重启该来源的调度任务。
5. 需要立即更新时，使用顶部刷新按钮。刷新全部来源时只请求当前已启用的数据源。

### 添加自定义来源

1. 打开“设置 > 数据源”，在“添加 RSS / Atom 来源”中选择常用技术社区预设，或手动填写显示名称和完整 Feed URL。
2. 点击“添加”。Signal 会实际请求该地址并确认它能解析出 RSS/Atom 文章，同时根据域名识别已知平台图标。
3. 添加成功后，该来源默认启用、订阅并每 60 分钟同步一次；可继续调整开关和间隔。
4. 用户来源右侧提供删除按钮。删除配置不会把普通网页伪装成 Feed，也不会提交任何本地文章到仓库。

首版只接受可验证的 RSS/Atom URL，不执行任意网页采集规则。若网站只提供普通首页，应先找到其官方 Feed 地址。

内置预设包括 SegmentFault、OSCHINA、博客园、Ruby China、InfoQ 中文、DEV Community、Lobsters、Rust Users Forum、Rust Internals、Python Discussions 和 Go Forum。预设只会填入名称和 URL；点击“添加”时仍会实际请求并验证 Feed。上游关闭 Feed 或更改访问策略时，该预设会明确添加失败，不会写入占位数据。

应用启动后，每个已启用来源会立即执行一次同步，之后按各自间隔运行。上游限流、登录墙、接口变更或网络错误可能导致单次同步失败；这不会把占位文章写入数据库。

Reddit 默认关闭。在当前匿名访问环境中，上游可能返回 HTTP 403；只有确认所在网络可以匿名访问该接口后再启用。Product Hunt 当前没有注册为数据源，不能仅通过设置打开。

## 配置掘金或知乎 Cookie

掘金和知乎的公开列表无需登录即可尝试同步。Signal 也允许把可选 Cookie 附加到这两个来源的请求：

1. 在已登录的浏览器会话中取得对应站点的 Cookie 请求头值。
2. 打开“设置 > 来源登录”。
3. 在对应来源中填入 `name=value; another=value` 形式的值，不要包含 `Cookie:` 前缀。
4. 点击“保存登录态”，再手动刷新该来源。

Cookie 会保存在操作系统凭据存储中，并在应用重启后恢复；`settings.json` 只保存非敏感配置。旧版明文 Cookie 会在首次启动新版本时尝试迁移并从设置文件清除。Cookie 具有账号访问风险，不应粘贴到 issue、日志或聊天中；共享设备上应谨慎使用并及时清除。

当前限制：Signal 不自动读取浏览器 Cookie。界面提供前往源站登录和复制 Cookie 的说明；Cookie 只影响对应请求是否携带登录态。上游随时可能更改接口、登录方式或拒绝自动请求。

## 配置关键词过滤

1. 打开“设置 > 关键词过滤”。
2. 选择“黑名单”以隐藏包含任一关键词的条目，或选择“白名单”以只保留至少包含一个关键词的条目。
3. 输入关键词并按 Enter 或点击“添加”。
4. 点击已有关键词旁的删除按钮即可移除。

匹配不区分大小写，作用于文章标题和摘要。本地全文搜索和各工作区读取都会使用当前过滤配置；白名单为空时不限制结果。

## 配置 AI Provider

打开“设置 > AI”，按所用协议填写以下内容：

| 协议 | 默认 API 地址 | 请求接口 | API Key |
|---|---|---|---|
| OpenAI Compatible | `https://api.openai.com/v1` | Chat Completions | 必需 |
| Anthropic Messages | `https://api.anthropic.com` | `/v1/messages` | 必需 |
| Google Gemini | `https://generativelanguage.googleapis.com` | `generateContent` | 必需 |
| Ollama | `http://localhost:11434` | `/api/chat` | 不需要 |

配置步骤：

1. 选择 Provider。切换 Provider 时，如果仍在使用上一协议的默认地址，界面会自动换成新协议的默认地址。
2. 填写服务端实际存在的模型名称。Signal 不自动下载模型，也不猜测账号可用模型。
3. 确认 API 地址。远程地址必须使用 HTTPS；HTTP 只允许 `localhost`、`127.0.0.1` 或 IPv6 回环地址。地址不能包含用户名、密码、查询参数或片段。
4. 云协议输入 API Key 并点击“保存”。凭据按协议分别写入操作系统凭据存储，不进入 SQLite 或 `settings.json`。Ollama 不读取云协议凭据。
5. 选择是否启用“生成后人工审核”。默认开启，结果先保存为可编辑草稿；关闭后生成结果直接标记为已接受，但不会自动创建知识库笔记。
6. 点击“测试连接”。测试不仅查询模型，还会执行一次最小 JSON 生成并走与 AI 搜索/洞察相同的响应解析路径。
7. 打开一篇有摘要或缓存正文的文章，确认发送内容后生成一次洞察，进一步验证模型对完整提示的遵循能力。

OpenAI Compatible 表示服务需要兼容当前使用的 Chat Completions 请求。Signal 可读取标准响应、常见内容分段、SSE 和 Responses 风格文本字段，也会从带说明文字或 Markdown 围栏的结果中提取 JSON；具体模型、路径、鉴权和 `response_format` 支持仍由服务提供方决定。

### 使用 AI 搜索

AI 搜索不是独立的互联网搜索引擎。提交问题后，Signal 会先从本地全文索引找出匹配文章，并补充近期已采集内容作为候选；随后将候选摘要交给已配置模型归纳回答。模型可以补充稳定背景知识，但回答会区分本地采集证据和模型知识。

因此，AI 搜索无法保证覆盖未被 Signal 采集的网站、刚发生的事件、登录后内容或实时行情。需要核验时，请打开返回的本地文章或原文，而不要把模型回答当作实时引用。

### 生成文章思维导图

1. 先按本节完成 AI Provider 配置并通过“测试连接”。
2. 打开文章阅读区，从文章操作菜单选择“文章思维导图”。
3. 点击“生成思维导图”。Signal 仅在这一步发送内容给所选模型：优先发送缓存正文；没有缓存正文时发送来源摘要，最长为 24,000 个字符。
4. 生成成功后可以缩放、查看节点与关系，并关闭窗口。导图按文章保存到本机，关闭或重启应用后仍可再次打开。
5. 需要更新时点击“重新生成”。这会以新的结果替换该文章之前保存的导图，不能恢复被覆盖的版本。

导图由模型根据文章内容归纳，可能遗漏、误解或组织不当；请以原文为准。文章没有正文和摘要、模型未配置或服务未返回可解析的结构化结果时，无法生成导图。

## 使用 Ollama

1. 安装并启动 Ollama。
2. 在终端准备模型，例如 `ollama pull qwen3:8b`。
3. 在 Signal 中选择“Ollama”，保持默认地址或填写实际本机地址。
4. 模型名称必须与 `ollama list` 中显示的名称一致。
5. 点击“测试连接”，再对一篇文章执行生成。

Signal 不负责启动 Ollama。若服务未监听、模型未下载或模型不支持稳定 JSON 输出，连接或生成会失败。

## 更换或删除 API Key

每个云协议使用独立凭据。切换 Provider 不会把一个协议的 Key 复制给另一个协议。

- 在 API 凭据输入框填写新值并点击“替换”，即可覆盖当前协议的 Key。
- 点击“移除”，再点击一次“确认”，即可删除当前协议的 Key。
- 删除 Key 不会删除本地文章、AI 历史结果或模型地址设置。
