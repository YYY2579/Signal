# 隐私与本地数据

Signal 采用本地优先设计：文章、阅读状态和 AI 结果默认保存在当前设备，没有 Signal 自建账号或同步服务。但“本地优先”不代表完全离线；数据源同步和用户主动调用 AI 都会连接外部服务。

## 本地保存什么

Signal 使用 Tauri 提供的操作系统应用数据目录，不依赖固定的用户目录路径：

- `signal.db`：文章元数据、缓存正文、阅读状态、收藏、稍后阅读、知识库标记、笔记、AI 洞察和热度快照。
- `settings.json`：数据源开关、订阅、刷新间隔、关键词过滤、掘金/知乎 Cookie、AI Provider、API 地址、模型名称和审核偏好。
- 系统凭据存储：按 AI 协议分别保存云服务 API Key，例如 macOS 钥匙串或 Windows 凭据管理器。

API Key 不写入 SQLite 或 `settings.json`。Ollama 不需要 Key，也不会读取已保存的云服务凭据。来源 Cookie 当前属于普通应用设置，不享有与 API Key 相同的系统凭据保护。

## 什么时候会联网

| 操作 | 连接对象 | 发送内容 |
|---|---|---|
| 自动或手动刷新 | 已启用的数据源 | 来源所需的列表请求；掘金/知乎可附带用户保存的对应 Cookie |
| 打开未缓存正文 | 文章所属来源 | 文章 ID 或原文 URL，以及该来源可选 Cookie |
| 打开原文 | 默认浏览器和原站 | 原文 HTTPS URL |
| 测试 AI 连接 | 用户配置的模型服务 | API Key 鉴权、模型名称及协议要求的验证请求 |
| 生成文章洞察 | 用户配置的模型服务 | 标题、来源、作者、缓存正文或摘要，以及 Signal 的结构化分析提示 |
| AI 搜索 | 用户配置的模型服务 | 用户问题和最多 40 篇本地候选文章的 ID、标题、来源及摘要摘录 |

文章洞察在发送前显示确认对话框。AI 搜索只会在用户主动提交问题时发送候选摘要。云 API Key 作为请求头直接交给用户配置的服务，不会放进提示词；Signal 项目本身没有代理这些请求的服务器。

## 信任边界

- 数据源内容是不受信任的外部数据。AI 系统提示会要求模型不要遵循文章中的指令，但这不能完全消除提示注入或错误输出风险。
- 自定义 AI Base URL 决定内容和凭据的接收方。远程地址必须是 HTTPS，本地 HTTP 只允许回环地址；配置前仍需确认域名和运营方。
- 来源 Cookie 可以代表已登录会话。不要复用到不可信环境，也不要提交到仓库、issue、日志或截图。
- 原文和 AI 服务各自受其隐私政策、日志保留和辖区约束。Signal 无法控制第三方如何处理收到的数据。

## 删除和备份

应用内移除某个 AI Key 只删除当前 Provider 在系统凭据存储中的条目，不会清除文章、设置或历史 AI 结果。

Signal 当前没有内置的整库导出、云同步或“一键清除全部数据”功能。需要备份或删除时，应先退出应用，再通过操作系统管理该应用的应用数据；API Key 仍需在 Signal 中逐个移除，或使用操作系统的凭据管理工具处理。操作前应自行备份需要保留的笔记。
